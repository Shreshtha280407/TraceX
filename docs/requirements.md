## Data meaning rules

- An address or script identifier is not a person or a wallet. A script association says only that an output is locked to that identifier.
- A transaction spends prior outputs and creates outputs. Do not allocate a given input to a given output unless a separately evidenced method says so.
- An IP/port observation is an observation of a peer/relay in a capture context. It does not establish transaction origin or wallet ownership.
- `block_time`, `observer_received_at`, and `ingested_at` have different meanings. Unknown is represented as `null`, never as a made-up default.
- An anomaly/rank is triage priority, not probability of criminality. Phase 0 contains no ranking artifact.

## Incoming-data intake checklist (blocking before Phase 2)

1. Save the original file bytes immutably; record SHA-256, size, source authority, licence, acquisition note, and consent/handling restrictions.
2. Record format, compression, encoding, exact header/paths, row count, nested-list form, supported network, field types, and maximum observed widths.
3. Map every field to `schemas/v1` or record an explicit unsupported/quarantine decision. The published minimum fields are retained in v1, including source/destination endpoint fields and geo/ASN. Do not infer `vout`, ownership, timestamps, or labels.
4. Establish what each time means and its timezone/clock quality; establish whether labels are ground truth, analyst annotation, or synthetic scenario labels.
5. Confirm whether `prev_txid` and `prev_vout` exist. If not, mark spend-lineage coverage partial and use only participation associations.
6. Attach the completed inspection as a new source entry in `data_manifest.json`; do not overwrite the synthetic fixture record.

## Phase 0 exit evidence

The v1 schemas define case, source, transaction, input, output, address/script, network observation, candidate link, finding, and review. Examples make their meanings inspectable. `python3 fixtures/demo_100k/generate.py --verify` regenerates and validates the fixture from its pinned seed, and `python3 -m unittest discover -s tests -v` verifies schema-shaped examples and fixture invariants.
